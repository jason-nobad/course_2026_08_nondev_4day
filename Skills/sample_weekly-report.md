# 스킬: 주간 업무 보고 초안 작성 (구매팀)

> 📎 **샘플(가상 사례)** — ㈜가온물산 구매팀의 "주간 업무 보고 자동화" 예시입니다. 회사·인물·수치는 모두 가상이며, 실습 시 본인 업무로 바꿔 쓰세요.
>
> **근거:** 구매팀 주간 보고 양식 v3(2026-06 개정, `_workspace/01_input/sample_report_template.md`) · 실습 주제 카탈로그 01 「주간 업무 보고 자동화」
> **관련 문서:** 용어집 [`sample_glossary.md`](sample_glossary.md) · 금지 행동 [`sample_prohibited.md`](sample_prohibited.md) · 흐름도 [`../Workflow/sample_workflow.md`](../Workflow/sample_workflow.md) · 검증 체크리스트 [`../Outputs/sample_checklist.md`](../Outputs/sample_checklist.md)

## 1. 목적과 사용자

- **목적:** 매주 금요일 오전, 팀원별 업무 메모와 지난주 보고를 취합해 **팀장에게 보내는 주간 보고 초안**을 만든다. 담당자가 90분 걸리던 취합·정리를 20분 이내로 줄이는 것이 목표.
- **결과물을 받는 사람:** 1차 — 구매팀장(승인자). 2차 — 팀장 승인 후 경영지원본부 주간 회의 자료로 발췌·공유.
- **AI의 역할:** 분류·정리·양식 적용·변경점 표시까지. **판단(지연 사유의 타당성, 대외 공유 범위)은 사람이 한다.**

## 2. 입력

| 입력 | 형식 | 위치 |
|------|------|------|
| 팀원별 업무 메모 (팀원 3명) | 마크다운, 5개 절(완료·진행·지연·다음 주·이슈) | `_workspace/01_input/<케이스>/memo_이름.md` |
| 지난주 보고서 (승인본) | 마크다운 | `_workspace/01_input/sample_last_week_report_YYYY-MM-DD.md` |
| 보고 양식 | 마크다운 | `_workspace/01_input/sample_report_template.md` |
| 이번 주 기간 | 날짜 (월~금) | 지시문에 명시 |

입력이 하나라도 없거나 비어 있으면 **초안을 만들지 말고 "확인 필요"로 멈춘다** (금지 행동 6-1).

## 3. 작업 절차

1. **입력 검사** — 메모 3건이 모두 있는지, 비어 있지 않은지, 실명·연락처·계좌 등 **비식별 위반**이 없는지 확인. 위반 시 즉시 중단.
2. **분류** — 각 메모의 항목을 완료 / 진행 중 / 지연 / 다음 주 계획 / 이슈·요청사항 5가지로 분류. 메모의 절 제목을 그대로 따르고, 절이 모호하면 "확인 필요" 표시.
3. **지연 항목 점검** — 지연 항목에는 반드시 **사유**가 있어야 한다. 사유가 없으면 항목 뒤에 `[확인 필요: 사유 없음]`을 붙인다. 사유를 지어내지 않는다.
4. **지난주 대비 변경점 표시** — 지난주 "진행 중"이었다가 이번 주 "완료"된 항목에 `◀ 지난주 진행 → 완료`, 지난주에도 지연이었던 항목에 `⚠ 2주 연속 지연` 표시.
5. **수치 표시** — 금액·단가·수량·%가 들어간 문장은 **원문 그대로** 옮기고 `[수치 원문 대조]` 태그를 붙인다. 합계·증감률을 계산하지 않는다.
6. **양식 적용** — 보고 양식 v3의 절 순서·제목을 그대로 사용. 각 항목은 개조식 1줄, 담당자 이름을 괄호로 표기.
7. **초안 표시** — 문서 맨 위에 "AI 초안 — 팀장 승인 전 · 대외 공유 금지", 맨 아래에 "검토 필요 항목" 목록을 자동으로 넣는다.
8. **자체 점검** — 완성 기준(§4) 체크리스트를 스스로 확인한 뒤 `_workspace/02_working/`에 저장. 담당자 검토 → 팀장 승인 후 `03_final/`로 이동.

## 4. 출력 형식과 완성 기준

**출력 형식** — 보고 양식 v3 (절 5개, 각 항목 개조식 1줄):

```
# 구매팀 주간 업무 보고 (YYYY-MM-DD ~ YYYY-MM-DD)
> AI 초안 — 팀장 승인 전 · 대외 공유 금지
## ① 이번 주 완료
## ② 진행 중
## ③ 지연 (사유 포함)
## ④ 다음 주 계획
## ⑤ 이슈·요청사항 (팀장 결정 필요 항목은 맨 위)
---
검토 필요 항목: …
```

**완성 기준 (모두 만족해야 통과):**

- [ ] 5개 절이 양식 순서대로 있고, 항목마다 담당자 이름이 있다
- [ ] 지연 항목마다 사유가 있거나 `[확인 필요: 사유 없음]` 표시가 있다
- [ ] 지난주 대비 변경점(◀, ⚠)이 표시되어 있다
- [ ] 수치가 들어간 문장에 `[수치 원문 대조]` 태그가 있고, 계산된 숫자가 없다
- [ ] 문서 위·아래에 "AI 초안 — 팀장 승인 전" 표시와 "검토 필요 항목" 목록이 있다
- [ ] 팀원 이름·협력사명 외에 개인 연락처·실명 고객·계좌·실제 계약 금액이 없다
- [ ] 각 항목이 개조식 1줄(40자 안팎)이다 — 문단으로 풀어 쓰지 않았다

## 5. 우리 팀 용어집 (요약 — 전체는 `sample_glossary.md`)

| 용어 | 뜻 |
|------|------|
| PO | 구매 주문(Purchase Order). "PO 발행"은 발주 확정을 뜻함 |
| PR | 구매 요청(Purchase Request) — 현업 부서가 구매팀에 올리는 요청. Pull Request와 혼동 주의 |
| MRP | 자재 소요계획. 매월 초 확정 |
| 단가계약 | 연 단위 협력사별 단가 합의. "갱신"은 계약 연장 서명 |
| 지연 | 계획 대비 1주 이상 늦어진 항목. 반드시 사유·재조정 일정 병기 |

## 6. 금지 행동 (이유와 함께 — 전체는 `sample_prohibited.md`)

- **6-1. 입력이 없거나 비면 지어내지 않는다** — 메모 미제출 팀원의 업무를 추정해서 채우면 "보고서에 없는 일"이 생긴다. `[미제출]`로 표시하고 멈춘다.
- **6-2. 지연 사유를 단정하지 않는다** — "담당자 태만으로 지연" 같은 원인 추정은 개인 평가로 읽힌다. 메모에 적힌 사유만 옮기고, 없으면 "확인 필요".
- **6-3. 금액·단가·수량을 계산하지 않는다** — 합계·증감률 오류가 그대로 상위 보고에 올라간다. 원문 그대로 + `[수치 원문 대조]`.
- **6-4. 개인 성과 비교 표현 금지** — "A는 3건, B는 1건 처리" 식 나열은 팀 보고의 목적이 아니다. 항목별 담당자 표기까지만.
- **6-5. 대외 공유 범위를 임의로 정하지 않는다** — 경영지원본부로 보낼 발췌는 팀장이 정한다. 초안은 항상 "대외 공유 금지" 표시.
- **6-6. 실데이터·개인정보 사용 금지** — 이 스킬은 비식별 샘플로 검증됐다. 연락처·계좌·실명 고객 정보가 입력에 보이면 즉시 중단.
