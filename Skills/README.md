# Skills/ — 스킬(AI 업무 매뉴얼)

우리 팀의 **스킬**을 모아 두는 폴더입니다. 스킬 = 검증된 지시 요령을, 누가 써도 같은 품질이 나오도록 문서로 표준화한 "AI용 업무 매뉴얼".

## 언제 무엇을 넣나

| 날짜 | 넣는 것 | 권장 파일 이름 |
|------|------|------|
| 1일 실습 2 | **스킬 v0** — "AI에게 뭘 알려줬더니 잘 됐나" 메모 | `내업무명.md` (예: `weekly-report.md`) |
| 1일 과제 | **용어집**·**금지 행동** 초안 | `glossary.md`, `prohibited.md` |
| 2일 실습 1 | 스킬 v0 → **v1.0 완성** → PR 올리기 → 페어 교차 리뷰·승인 → 병합 | 같은 파일을 고쳐 PR로 제출 |
| 이후 | 규정·양식이 바뀌면 버전을 올리고(v1.1, v1.2 …) 변경 사유 한 줄 기록 | 파일 안 "버전과 변경 기록" 표 |

## 스킬 문서 뼈대 (7항목)

본보기: [`../References/skills.md`](../References/skills.md) (KS A 0001 표준 문서 작성 스킬), [`../References/design.md`](../References/design.md) (웹 디자인 스킬)

```markdown
---
name: 스킬-영문-이름
description: 언제 이 스킬을 쓰는지 한두 문장
---

# 스킬: (한글 이름)

## 1. 목적과 사용자      — 무엇을 위해, 결과물을 누가 받는가
## 2. 입력              — 무엇을 재료로 주는가
## 3. 작업 절차          — 순서대로, 번호를 붙여서
## 4. 출력 형식과 완성 기준 — 체크리스트로 ("무엇이 통과인가")
## 5. 우리 팀 용어집      — 팀에서만 통하는 말 (예: "PO"는 구매 주문)
## 6. 금지 행동          — 무엇을 하면 안 되는지, **이유와 함께**
## 7. 버전과 변경 기록    — v1.0 / 날짜 / 작성 / 변경 내용 표
```

- 좋은 예시 1건 + 나쁜 예시 1건이 규칙 10줄보다 효과적입니다.
- "모르면 멈추고 '확인 필요'로 표시"를 금지 행동에 꼭 넣으세요.
- 예시 입출력에도 **비식별 데이터**만 사용합니다.
