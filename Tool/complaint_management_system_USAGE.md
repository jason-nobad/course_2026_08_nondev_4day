# 전자문서산업계 애로사항·민원 통합관리 시스템 — 사용법과 검증 기록

> 근거 문서: `Downloads/prd.txt` (PRD v1.0) · 화면 목업: `docs/prd_img/01~10_*.png`
> 도구 본체: [`complaint_management_system.html`](complaint_management_system.html) — 브라우저에서 더블클릭으로 바로 실행되는 단일 HTML 파일(웹서버·설치 불필요)

## 한 줄 명세

**전화·이메일 등으로 들어온 회원사 애로사항을 접수번호(EDPA-연도-번호)로 등록하면 → 담당자 배정 → 검토/기관협의 → 정책건의 연결 → 종결까지의 처리 과정과 이력이 한 화면에서 관리되고, 대시보드·통계·오늘의 업무 화면에서 누구나 처리 현황을 확인할 수 있다.**

| 항목 | 내용 |
|---|---|
| 용도 | PRD §33 "MVP 범위(필수)" 전 항목 구현: 회원사·민원 등록/조회/검색, 상태·기한 관리, 처리이력, 기관협의, 정책건의(민원 다대다 연결), 대시보드, 통계, 알림, 권한(역할별 UI), 감사로그 |
| 입력 | 화면에서 직접 입력(민원 등록 마법사, 처리이력/기관협의/정책건의 등록 폼). 별도 파일 입력 없음 |
| 출력 | 브라우저 화면 + `⬇ 엑셀 다운로드`(CSV, 민원 목록) + `🖨 PDF 보고서`(인쇄 다이얼로그로 저장) |
| 실행 환경 | Chrome·Edge 등 최신 브라우저. 설치·서버 없음. 데이터는 브라우저 **localStorage**에 저장(이 PC·이 브라우저에만 남음, 다른 사람과 공유하려면 관리자 → 데이터 관리 → 백업(JSON) 내보내기/복원 사용) |
| 내부 구조 | 한 개의 HTML 파일 안에서도 **Backend**(데이터 저장·검증·권한·감사로그를 담당하는 `Backend.*` 함수 모음)와 **Frontend**(화면을 그리고 사용자 입력을 받아 `Backend.*`를 호출하는 render/view/submit 함수들)를 코드상 분리했습니다. 화면 쪽 코드는 데이터를 직접 건드리지 않고 반드시 `Backend.createComplaint()`처럼 이름 붙은 함수를 통해서만 값을 바꾸며, 이 함수들은 실제 서버 API처럼 `{ok, message, data}` 형태로 응답합니다. 네트워크 통신은 없고(로컬 함수 호출), 향후 진짜 서버로 옮길 때 이 `Backend.*` 함수들을 그대로 API 엔드포인트로 옮기면 되는 구조입니다. |
| 전제 조건·알려진 한계 | ① 첨부파일은 데모 목적상 **파일명만 기록**되고 실제 파일 내용은 저장하지 않음. ② 로그인은 화면 우측 상단 "사용자 전환" 드롭다운으로 시뮬레이션(실제 인증 없음). ③ 권한 검사는 화면(버튼 숨김)과 `Backend.*` 함수 양쪽에서 이중으로 이뤄지지만, 브라우저 개발자 도구에서 `Backend.xxx()`를 직접 호출하면 우회할 수 있음 — 사내 배포용이 아닌 데모/1단계 검증용. ④ 여러 PC·팀원 간 데이터 공유는 JSON 백업 파일을 주고받는 방식으로만 가능(실시간 동기화는 2단계에서 서버·DB 연동 필요, PRD §33 "2차" 참고) |

## 실행 방법

1. `complaint_management_system.html` 파일을 더블클릭하거나, 브라우저 주소창에 파일 경로를 입력해 엽니다.
2. 최초 실행 시 PRD 목업과 동일한 가상 사례(A~E기업, 홍길동 등 담당자, EDPA-2026-0101~0125)로 자동 채워집니다.
3. 좌측 메뉴에서 화면 이동, 우측 상단에서 로그인 사용자(역할)를 바꿔가며 권한별 화면 차이를 확인할 수 있습니다.
4. 데이터를 처음 상태로 되돌리려면 **관리자 → 데이터 관리 → 샘플 데이터로 초기화**.

| 정책건의·산업현안 | §13 정책건의 관리, §36 산업계 현안판 |
| 통계 | §23 통계 및 보고서 |
| 관리자(사용자·분류체계·권한 매트릭스·감사로그·데이터 관리 5개 탭) | §21 권한 관리, §8 분류체계(대분류·세부유형·접수경로를 직접 추가/삭제), §22 감사로그(민원·회원사·기관·정책건의·사용자·코드 변경 전체를 한 화면에서 조회), §33 데이터 관리(백업 JSON 내보내기/복원, 초기화) |

핵심 업무 규칙(PRD §29)은 코드로 반영했습니다: 담당자 미배정 민원은 "미배정" 배지로 표시(Rule 1), 처리이력 등록 시 다음 조치사항을 함께 입력(Rule 2), 처리기한은 오늘 날짜 기준으로 정상/임박/초과를 자동 계산(Rule 3), 종결 시 종결사유 선택 필수(Rule 4), 정책건의 하나에 여러 민원을 연결 가능(Rule 5).

## 검증 기록 — 샘플 3종 (2026-08-19, 헤드리스 Chrome 자동 실행으로 검증)

실제 파일을 브라우저로 로드해 각 화면을 렌더링하고, 버튼 클릭과 동일한 함수 호출을 자동 실행한 뒤 결과를 확인하는 방식으로 검증했습니다.

| 샘플 | 시나리오 | 기대 결과 | 실제 결과 | 통과/실패 |
|---|---|---|---|---|
| **정상** | 대시보드~관리자 8개 화면 전체 이동, 민원 상세 7개 탭 전체 열람, 신규 민원 등록 마법사(Step1~5) 끝까지 진행 후 저장, 저장된 민원에 처리이력→기관협의→종결까지 순서대로 처리, 신규 정책건의 생성, 알림 패널 열기 | 각 화면·탭이 오류 없이 렌더링, 등록 시 `EDPA-연도-번호` 형식 접수번호 자동 생성, 기관협의 등록 시 상태가 "관계기관 협의중"으로 자동 전환, 종결 시 종결사유 저장 | 29개 확인 항목 전부 통과 (화면 8 · 탭 7 · 등록 마법사 · 처리이력/기관협의/종결 · 정책건의 생성 · 알림 패널) | **통과 (29/29)** |
| **경계** | 처리기한이 "오늘"인 민원의 기한 상태 계산, 담당자를 배정하지 않은 민원의 알림·배지 표시 | 오늘 마감 민원은 "D-Day"(임박)로 표시, 미배정 민원은 알림 목록과 민원 목록에 "미배정"으로 표시 | 두 항목 모두 기대대로 동작 | **통과 (2/2)** |
| **오류** | 민원 등록 마법사에서 필수 항목(회원사)을 비운 채 저장 시도, 처리이력 등록 폼에서 처리내용을 비운 채 저장 시도 | 저장되지 않고 안내 메시지(토스트)만 표시, 입력 창은 닫히지 않고 유지되어 사용자가 바로 고칠 수 있어야 함 | 두 경우 모두 데이터가 추가되지 않았고, 입력 창이 유지됨 | **통과 (2/2)** |

**요약: 통과 5범주(정상 1묶음 29건, 경계 2건, 오류 2건) — 총 33/33.** 검증 방법: 저장소 내 임시 테스트 파일에 위 시나리오를 스크립트로 추가한 뒤 `chrome.exe --headless=new --dump-dom`으로 실행, 렌더링된 DOM과 내부 데이터 상태(`DB.complaints`, `DB.history` 등)를 대조. 검증 후 임시 파일은 삭제했으며 배포 파일(`complaint_management_system.html`)에는 테스트 코드가 포함되어 있지 않습니다.

### 추가 검증 — 권한 강화·관리자 기능 보강 (2026-08-19)

| 구분 | 시나리오 | 결과 |
|---|---|---|
| 회원사·관계기관 CRUD | 회원사/기관 추가·수정 | **통과** |
| 사용자 관리 | 관리자만 추가·수정·삭제 가능(비관리자는 버튼 자체가 없음, `Backend.saveUser` 직접 호출도 차단) | **통과** |
| 담당 건 권한 제한 | 담당자는 본인 담당(또는 미배정) 건만 처리 버튼 노출, 팀장은 같은 부서 건까지, 관리자는 전체, `Backend.addHistory` 등 서버 격 함수도 동일하게 이중 차단 | **통과** |
| 분류체계 관리 | 관리자가 대분류·세부유형·접수경로 추가/삭제, 비관리자는 `Backend.addType` 등 호출 시 차단 | **통과** |
| 전체 감사로그 | 민원·회원사·기관·사용자·분류체계 변경이 모두 한 화면(관리자→감사로그)에 기록·검색됨 | **통과** |
| 백업/복원 | JSON 백업 내보내기 → 다른 상태로 복원 시 데이터 원복, 손상된 JSON은 거부, 비관리자는 백업/복원/초기화 모두 차단 | **통과** |

검증 방법은 위와 동일(헤드리스 Chrome + 임시 테스트 스크립트, 검증 후 삭제)하되 이번에는 시나리오별로 파일을 나눠 실행해 각 단계를 개별 확인했습니다.
